# 问题三 B+ 代码交付与演练说明

本目录固定为 3 个文件：

- `q3_runner.py`：基础版 B 与增强版 B+ 共用的主程序。
- `q3_tools.py`：纯离线自检、演练真值补录、结果汇总。
- `README.md`：运行和防误操作说明。

适用环境：Windows 11、Python 3.13。程序只使用 Python 标准库，不需要安装第三方包。

## 1. 正式机会保护

1. 当前阶段只进入模拟器的 **问题3演练测试**，不要点击“问题3正式测试”。正式测试一旦在模拟器中启动就会消耗一次机会，Python 程序无法撤销。
2. `python q3_runner.py` 默认只作离线预览，不连接模拟器、不调用 `/enter`。
3. 演练必须同时写出 `--connect --mode practice`，并在终端输入 `PRACTICE-Q3`。
4. 正式模式由源码顶部的 `FORMAL_UNLOCKED = False` 硬锁。演练阶段必须保持为 `False`。
5. 接口不能告诉程序当前打开的是演练页还是正式页，所以人工核对模拟器页面不可省略。
6. 参赛队号不写死在共享代码中，连接前由终端输入；动作日志会自动将其替换为 `<redacted>`。

## 2. 首次必须先做离线自检

把整个 `Q3` 文件夹复制到队友电脑，在该目录打开 PowerShell，先运行：

```powershell
python q3_tools.py self-test
```

它只检查以下内容，绝不连接模拟器：

- 七点1000 m圆覆盖；
- 12条动态外围路线均访问全部外围点且长度均为6900 m；
- 测向角域外包与跨0°角度；
- 最小覆盖圆；
- 线段上的保证接收/保证清除区间；
- 28 m保底网格及排除圆删格；
- 保证接收补测候选。
- 外围正六边形内、外、穿越与接触边界判定；
- 单点和直径分割两点保证覆盖；
- 两点清除顺序、最坏分支时间和开放路线滚动排序；
- 普通补测一次后必须返回全局重规划。

必须看到全部 `PASS` 和“全部离线自检通过”后，才允许开始演练。

再运行默认离线预览：

```powershell
python q3_runner.py
```

它应明确显示不会连接模拟器。本版本已在生成代码的电脑上通过离线语法检查和 `self-test`；队友电脑复制后仍必须先重新执行一次。

## 3. 新增强版 B+ 的演练命令

1. 启动模拟器并联网登录。
2. 只进入 **问题3演练测试**。
3. 等待5秒倒计时完全结束，肉眼确认“机器狗接口已经就绪”。
4. 记录模拟器显示的案例编码。
5. 在 `Q3` 目录运行以下命令，把引号内文字替换为真实案例编码：

```powershell
python q3_runner.py --connect --mode practice --strategy bplus --case-code "真实案例编码"
```

6. 按提示输入当前登录模拟器的参赛队号。
7. 再次核对当前确为问题3演练测试，然后输入：

```text
PRACTICE-Q3
```

只有完成上述人工确认，程序才会连接并调用 `/enter`。

## 4. B+ 严格采用的策略

正确性骨架始终不变：

```text
逐频道七点保证搜索
→ direction 建立保守定位域
→ near 原地立即清除
→ 最小覆盖圆半径不超过19.9 m才作保证单点清除
→ 经直径方向凸区域分割证明后允许保证两点清除
→ 必要时用28 m完整网格保底
→ 20频道全部已清除或已排除，或成功清除16频道后结束
```

B+增加以下省时规则：

1. **动态等长外围路线**：原点扫描后，在6个起点和顺逆时针共12条等长路线中，优先选择较早提供保证接收和较好交会机会的路线；仍访问全部必要外围点。
2. **既有停靠点一点多用**：在外围点、专项补测点和保证清除点，最多附加检测2个已发现频道。附加频道必须在该点保证接收、未在同一坐标测过，并且代表情景下预计一次补测可进入清除，或最小覆盖圆半径至少缩小20%。
3. **每条必经线最多一个零绕路停车点**：停车点严格位于当前点至下一托底点的线段内部，因此不增加搜索移动距离；优先作保证清除，否则最多补测2个强候选频道。
4. **沿途保证清除**：只有路线上的某点能够用19.9 m圆完整覆盖频道的保守定位域时才清除，不进行概率性试清除。
5. **排除圆缩减28 m网格**：只有整个方格都落入历史1000 m无信号圆或20 m清除失败圆时才删格；边界不确定格继续保留。
6. **外侧源最近保底点机会**：只有完整保守定位域与外围正六边形分离时才启用。到达该区域的最近外围点后，比较现在清除与推迟一段的完整最坏时间；执行后直接接到下一保底点，不原路返回。
7. **一点/两点保证清除**：单圆不能覆盖时，沿定位区域直径方向分成两个凸子区域。只有两个子区域分别被19.9 m圆完整覆盖时才执行，不是概率性试清除。
8. **逐宏任务滚动开放路线**：清除阶段为每个活动频道只生成一个下一安全宏任务，用最近插入加一轮2-opt排序。只执行第一个宏任务便根据真实反馈重排，不再为了节1 s换频而长时间锁定单源。

本版不按已发现源数分阶段。全程使用同一套B+规则；已发现数量不会改变几何判据或路径阈值。

补测前的代表情景抽样只决定效率排序，不承担接收、清除或完成证明。真正的保证始终由完整保守定位域核验。

程序不会使用以下复杂或冒险方法：

- 不跳过尚未完成的逐频道托底任务；
- 不采用不能保证接收的专项补测点；
- 不在最小覆盖圆半径大于20 m时试清除；
- 不使用神经网络、遗传算法、强化学习或完整旅行商优化；两点清除是经严格联合覆盖证明的例外，不是试清除。
- 不实现四叉树、完整未来反馈树或全局价值函数。

## 5. 基础版对照命令

同一份主程序可以关闭所有B+混合规则，运行原基础版 B：

```powershell
python q3_runner.py --connect --mode practice --strategy baseline --case-code "真实案例编码"
```

基础版仍使用相同的接口、定位域、最小覆盖圆、网格和日志代码，区别只在调度策略。因此更适合作为对照，避免两份源码产生无关差异。

官方演练案例随机生成，不能把不同案例称为严格配对实验。应先检查两组是否都保持全部清除，再比较多局平均定位清除时间、移动距离和检测数。若要严格同案例对照，只能使用另行构造的离线模拟案例。

## 6. 日志和结果补录

每次连接后自动生成：

```text
runs\时间_模式_策略_案例编码\
  actions.jsonl
  summary.json
```

`actions.jsonl` 保存必要的逐条请求与响应，参赛队号已经脱敏。`summary.json` 保存：

- 案例编码和策略；
- 清除数、虚拟总时间、平均定位清除时间；
- 现实程序运行时间；
- 移动距离、检测数、频道切换数、清除成功/失败数；
- 外侧位置机会数、单/两点清除宏任务数、两点首点成功数、机会绕路和滚动重规划数；
- 每个频道的最终状态、示向观测数、定位域直径和最小覆盖圆半径；
- 完成原因或异常原因。

演练结束后，从模拟器界面读取真实干扰源总数。示例：运行目录为 `runs\某次运行目录`、真实源数为13，则执行：

```powershell
python q3_tools.py add-truth "runs\某次运行目录" 13
python q3_tools.py summarize
```

汇总结果写入 `runs_summary.csv`。评价顺序必须是：

1. `end_reason=completed_by_program`；
2. `clear_fraction=1.0`；
3. 没有错误、保证清除失败或未解决频道；
4. 正确性均通过后，再比较 `average_location_clear_time_s`；
5. 同时查看移动距离和检测数，判断省时来自哪里。

## 7. 参数与保底说明

- 19.9 m：20 m清除半径内的0.1 m数值余量，不是新的物理误差。
- 999.8 m：1000 m最小接收半径内的0.2 m数值余量。
- 20%半径缩小、每点最多2个附加频道：B+的演练参数，只影响效率，不影响正确性。
- 6 s：“现在处理”与“推迟一段”的相近方案缓冲，只影响外侧位置机会排序。演练阶段可将 `BPLUS_INSERTION_BUFFER_S` 分别设为0、6、12做敏感性对照。
- 补测达到6次或连续2次低收益：转入28 m保证网格，避免反复购买低价值信息。
- 单源网格超过500点只报警，不再因此放弃频道。
- 总动作保护值为10000，用来防止实现异常循环；正常策略应远低于该值。正式测试前必须用演练最大动作数复核该保护值不会截断合法任务。
- 剩余现实时间进入20秒保护区时停止产生新动作并尽力退出。若演练接近这一保护区，说明实现或候选计算存在高风险，不能直接进行正式测试。

## 8. 异常处理

- `accepted=false` 或HTTP错误：停止并记录，不把未执行动作计入统计。
- 网络超时或连接中断：同一动作最多重试3次，完整复用原请求体和 `request_id`。
- 重试仍失败且接口可能已经关闭：停止，不再调用 `/exit` 查询原因。
- 保证接收点返回 `no_signal`、`near` 后原地清除失败：视为规则、实现或接口状态矛盾，安全停止。
- 19.9 m单点完整覆盖后清除失败：保留异常记录并进入28 m有限网格；两点联合覆盖的第二点仍失败则立即安全停止。
- 网格全部执行仍未清除：视为定位域外包或接口异常，安全停止。
- 运行中需要人工停止：终端按 `Ctrl+C`。正式测试即使手工中止也会占用机会。

不要同时启动两份主程序，不要并发向模拟器发送动作，不要在运行中编辑源文件。
