# 问题三 B / B+ 程序

本目录实现“区域分块与可验证保底 + 时间优化与 H(S) 动态调度”。程序仅适用于问题三的全向干扰源；可执行口径见 `SPEC.md`，历史结果失效说明见 `REBUILD_NOTICE.md`。

- `B`：固定七点逐频道托底，搜索结束后执行认证清除。
- `B+`：与 B 共用安全核心，额外使用少量补测候选、任务池、位置机会、等待段数与双层时间账本。

## 文件

- `config.py`：题面参数与团队设定的集中配置。
- `models.py`：频道、机器狗、动作、清除方案和运行摘要数据类型。
- `geometry.py`：7 点覆盖证书、七责任区解析证书、5 m 保守网格、区域更新、最小外接圆和清除覆盖。
- `planner.py`：补测候选、三分支代表情景评分、清除路线三候选和局部插入评价。
- `strategy.py`：B/B+ 状态机、任务池、H_hat 和安全模式。
- `client.py`：串行 HTTP 客户端；不确定的变异请求不盲目重发。
- `local_simulator.py`：不联网的全向源模拟器。
- `run.py`：正式接口运行入口、自有 JSONL 日志和摘要。
- `robot_dog.py`：可直接交给模拟器演练使用的启动脚本。
- `evaluate.py`：基线与主方案的同案例比较。
- `test_q3.py`：几何、协议计时、状态和端到端测试。

## 运行

在项目根目录执行：

```powershell
py -3 -m unittest Q3.test_q3 -v
py -3 -m Q3.evaluate --seed-start 51000 --cases 30 --workers 8 --mode both --output Q3/runs/b_bplus_dev_v1.json
py -3 -m Q3.evaluate --seed-start 52000 --cases 30 --workers 8 --mode both --output Q3/runs/b_bplus_independent_v1.json
py -3 -m Q3.sensitivity --cases 1 --workers 1 --output Q3/runs/b_bplus_sensitivity_v1.json
```

Q3运行只强制依赖 NumPy；最小外接圆的凸包预处理由内部二维算法完成，不再强制安装 SciPy。

连接模拟器前，先在演练模块等待接口就绪，再执行：

```powershell
py -3 -m Q3.run --robot-id "当前登录参赛队号" --mode B+ --log-dir Q3/runs/drill_01
```

`robot_id` 只通过启动参数传入，不进入源码。每次动作先写意图、响应后写结果与检查点；若指定日志目录已有上次结果，程序会自动新建本次运行子目录。网络状态不确定时安全停止，不能猜测远端状态后继续。

## 证据边界

- 7 点的 1000 m 圆盘覆盖有解析证书，并另做密集数值交叉检查。
- 逐频道排除以七个责任区分别获得单圆完整包含证书为准；顺路无信号检测可以替代相应托底任务。
- 网格更新和清除覆盖采用整格充分条件，允许多保留，禁止用采样点覆盖冒充连续覆盖。
- 代表点、三档误差和快速清除时间代理值只用于动作排序，不证明连续最坏值，也不是保证时间上界。
- H_hat 只负责排序；U_safe 分解为剩余托底、已发现频道认证清除和未来源保守预留，不承担实际预计耗时。
- B+ 在原点后比较顺、逆时针首段机会并固定一个六点环路方向；确定方向后的前两个外围点扫描全部尚未完成频道，以尽早获得第二次测向。巡航期以“前向补测预约”而非立即绕行管理已发现频道；预约点本身在所属前向段被直接复评，不能因候选池更新而无故丢失。每段至多执行两次预约；六边形外侧仅提高预约优先级，不再是补测的唯一准入条件。
- 专用补测点在主频道检测后，最多无移动追加2个高价值活动频道；每个活动频道最多积累5条有效 `direction`。前向段候选优先，走廊外候选只有较最佳前向方案至少节省6 s才允许采用。
- B+ 以有效 `direction` 条数而非总检测次数管理定位资源。只有一条方向且认证清除代理规模大的频道进入 `DIRECTIONAL_RESCUE`；其补测和同点复用只能使用保证接收的第二问式候选，每段最多一次，并强制回接下一外围点。无安全候选时保留后续预约；尾部仍无安全候选才记录原因并认证清除。
- 补测采用完整的最坏/最好反馈分支与直接清除作比较；未保证接收时，即使`no_signal`不缩小区域也必须计入最坏分支。超过6 s才作强接受或强拒绝，灰区只允许顺路复用。
- 清除失败后重新计算保守区域和覆盖次序；同一认证清除会话从当前位置连续推进更新后的路线，避免每个失败点都跨频道重排。
- 巡航结束后，未完成频道按认证清除簇进行带一步前瞻的路径排序；每簇持续完成，只有完成当前簇并接回另一簇可节省至少 6 s 时才允许打断。
- 5 m网格、候选数和6 s阈值在程序中是可测试的实现参数；只有根目录最新口径清单明确确认的内容才能写成团队统一口径。
- 多点覆盖与路线均为启发式可行方案，不称全局最优。
- `Q3/runs/` 中在 `REBUILD_NOTICE.md` 前生成的文件均为历史审计材料，不得论文取数；本地模拟也不替代正式模拟器验证。
